# Implementation Status

Design source: external product notes; not required at runtime.

## Implemented

- Review vault scaffold: `scripts/init-review-vault.js`.
- Daily folder structure: `01-daily/YYYY-MM-DD/1-原始错题素材` and `2-整理好的错题`.
- Per-subject weak-point pages for eight law-exam subjects.
- Deterministic JSON graph marking: `scripts/mark-graph.js`.
- User-supplied XMind marking with separate output: `scripts/mark-xmind.js`. Ingestion auto-marks `03-maps/<科目>/01-base/*.xmind` with confirmed knowledge points (red = 知识点不会, yellow = 易混点) to `02-marked/`.
- Knowledge-point confirmation gate: any knowledge point written to the knowledge library (by-knowledge files, subject collection pages, graph marking) must be user-confirmed. Mistake cards are organized directly without confirmation; unconfirmed knowledge points are reported as `knowledge_pending_confirmation`.
- Browser graph view: `scripts/render-graph-view.js`.
- Wrong-question ingestion into daily files, raw-material copies, subject weak-point pages, marked graph outputs, `mistake-index.json`, and `retest-queue.json`: `scripts/ingest-mistakes.js`.
- Metrics dashboard from durable records: `scripts/metrics-dashboard.js`.
- AI member learning-document template with `???` feedback area and study-log delta: `scripts/generate-learning-doc.js`.
- Seven-day retest result updates for closed-loop repair: `scripts/update-retest.js`.
- Pre-write confirmation sheet that hides the question, lists exact explanations for visibility, asks only for user-supplied knowledge points and one of two displayed cause tags, and treats confirmation as implied ingestion: `scripts/prepare-confirmation.js`.
- Runtime path resolution contract for user-specific vaults, technical workspaces, source materials, graphs, and backups: `references/path-configuration.md`.
- Core Obsidian Vault initialization with on-demand subject folders and persistent configuration: `scripts/init-review-vault.js`.
- Weekly review generation from the mistake index and retest queue: `scripts/generate-weekly-review.js`.
- Portable event-trigger automation plus optional macOS `launchd` configuration: `scripts/configure-automation.js`.

## Still Manual Or Data-Dependent

- OCR extraction from screenshots: currently performed by the agent or external OCR, not a standalone script.
- Question-bank exact matching: intentionally unavailable until a trusted `question_bank.json` exists.
- Automatic legal explanation generation: template exists; content should be generated by the agent with evidence and confidence.
- AI-generated practice questions: intentionally not authoritative; use only when the user asks for experimental practice.
- Payment/price-page validation: product experiment, not implemented in this local Obsidian workflow.
